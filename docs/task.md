# task.md: SubLoop Build Plan (Odoo x CUSAT Hackathon)

Legend: 🔴 must-have (in the problem statement) · 🟡 differentiator (helps us win) · 🟢 polish

Suggested team split (4 people): **A** Backend core · **B** Billing/Discount/Payments · **C** Frontend (Admin/Staff) · **D** Frontend (Portal/Dashboard) + DevOps/Docs/Demo.
Adjust to your headcount; with 3 people, merge C and D.

---

## Phase 0: Setup (first 1.5 hrs)
- [ ] Create monorepo (`apps/web`, `apps/api`, `packages/shared`)
- [ ] `docker-compose.yml`: Postgres, Redis, Mailpit
- [ ] Prisma schema (see architecture.md §4) + first migration
- [ ] Shared UI kit: Tailwind + shadcn/ui, layout shells for Admin / Staff / Portal
- [ ] CI: lint + typecheck on push; `.env.example`
- [ ] Agree API contract (OpenAPI/Swagger auto-generated by NestJS)

## Phase 1: Auth and Roles 🔴
- [ ] Signup: email unique (case-insensitive), password >8 chars + upper + lower + special (FE + BE)
- [ ] Login / logout / refresh token
- [ ] Forgot password → reset link email (hashed token, 30 min expiry, single use)
- [ ] Roles: Admin, Staff, Customer; `@Roles()` guard + ownership checks
- [ ] Admin-only "Add staff member" screen
- [ ] Seed: 1 admin, 2 staff, sample customers

## Phase 2: Catalog 🔴
- [ ] Products CRUD: name, type, sales price, cost price, notes
- [ ] Variants (attribute/value/extra price), e.g. Brand = Odoo → +560
- [ ] Plans CRUD: price, period (daily/weekly/monthly/yearly), min qty, available from/to
- [ ] Plan flags: auto-close, closable, pausable, renewable (per plan)
- [ ] Tax rules CRUD (percent / fixed)
- [ ] Discount rules CRUD (admin only): fixed/percent, min purchase/qty, dates, usage limit, scope (product / subscription)
- [ ] Quotation templates CRUD: plan + product lines + validity days

## Phase 3: Subscriptions 🔴
- [ ] Create subscription from scratch or **from quotation template**
- [ ] Auto number (`SUB-000123`), customer, plan, start/expiry, payment terms, lines (product, qty, unit price, tax, amount)
- [ ] State machine Draft → Quotation → Confirmed → Active → Closed with validation
- [ ] Pause / resume / renew / early close, gated by plan flags
- [ ] Status history timeline on the detail page (everyone can see where it stands)
- [ ] Worker: auto-close expired subscriptions where plan says so
- [ ] Quotation expiry after validity days

## Phase 4: Invoicing / Billing Engine 🔴
- [ ] Invoice generation from a subscription (customer, lines, taxes, totals prefilled)
- [ ] Tax calculation engine (decimal-safe)
- [ ] Discount engine: auto-applied to next invoice, stops on expiry or usage-limit hit
- [ ] Invoice status Draft → Confirmed → Paid (+ Cancelled)
- [ ] Actions: confirm, cancel, send (email), print (PDF)
- [ ] **Daily billing job** (BullMQ) with batch processing
- [ ] **Idempotency**: `UNIQUE(subscription, period_start, period_end)`; concurrency-safe usage counter
- [ ] Admin "Run billing now" + run summary (created / skipped / failed)
- [ ] Unit tests: no double billing, no skips, tax and discount math, expiry edge cases

## Phase 5: Payments 🔴
- [ ] Record payment: method, amount, date, note, against invoice
- [ ] Partial payments; auto-mark invoice Paid when fully covered
- [ ] Paid / outstanding / overdue views with filters
- [ ] Overdue derived from `due_date`; "send reminder" action 🟡

## Phase 6: Customer Portal 🔴
- [ ] Customer sees only own subscriptions and invoices
- [ ] View details, download invoice PDF
- [ ] Self-service actions allowed by plan (pause / close / renew request) 🟡
- [ ] Pay invoice (mock gateway checkout to simulate payment) 🟡

## Phase 7: Reports and Dashboard 🔴
- [ ] KPI cards: active subscriptions, revenue (period), outstanding, overdue count
- [ ] Filters (date range, plan, customer, status) + summary view
- [ ] Overdue invoices table with days late
- [ ] Revenue by month chart; payments by method chart
- [ ] CSV export
- [ ] 🟡 **MRR / ARR, churn rate, new vs. expansion revenue, upcoming renewals (next 30 days)**
- [ ] Redis cache (60s) + materialized view for trend

## Phase 8: Performance (<2s per page) 🔴
- [ ] Server-side pagination, sorting and filtering on all lists
- [ ] Indexes from architecture.md §4 verified with `EXPLAIN ANALYZE`
- [ ] Seed script: 10k+ subscriptions, 30k+ invoices, 20k+ payments
- [ ] **k6 load test**; screenshot p95 < 2s for the proof slide

## Phase 9: Differentiators 🟡 (only after all 🔴 are done)
- [ ] Proration on mid-cycle quantity change / upgrade
- [ ] Dunning: automated email reminders at +1/+7/+14 days overdue
- [ ] Audit log viewer (who changed what)
- [ ] Dark mode + mobile-responsive portal
- [ ] In-app notifications (renewal due, payment received)
- [ ] Global search (subscription no., customer, invoice no.)

## Phase 10: Polish and Delivery
- [ ] Empty/loading/error states everywhere; form validation messages
- [ ] Seed realistic Brightloop demo data (Odoo-brand variant +560, monthly + yearly plans, a discount)
- [ ] README with one-command run (`docker compose up`)
- [ ] Deploy live (Vercel + Render/Railway) as a backup to local demo
- [ ] Record a 3-minute backup demo video
- [ ] Pitch deck / final proposal PDF
- [ ] Rehearse demo twice with timing

## Demo Script (what judges should see, ~5 min)
1. Customer signs up (weak password rejected) → forgot-password email arrives.
2. Admin creates product with Odoo variant (+560), plan, tax, discount.
3. Staff builds subscription from a quotation template → Draft → Active.
4. Click **Run billing**: hundreds of invoices created in seconds; run again, **zero duplicates**.
5. Discount appears automatically on the next invoice.
6. Record payments (partial then full) → invoice flips to Paid.
7. Finance dashboard: MRR, revenue, outstanding, overdue, filters; show k6 results (<2s on 10k+ subs).
8. Customer portal: sees only their own data.

## Definition of Done
- Every requirement in the problem statement is demoable.
- No double billing across repeated runs (automated test passes).
- RBAC verified: customer cannot access another customer's data; staff cannot create staff or discounts.
- All list/report pages p95 < 2s on the seeded dataset.
